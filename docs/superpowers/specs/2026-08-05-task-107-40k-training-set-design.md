# Task 107 40K 无泄漏训练集设计

## 目标

把 Task 107 的 LoRA 训练集从 8,000 条扩展为 40,000 条，保持 `Yes`/`No` 各 20,000 条；不泄露当前测试集的任何精确 Payload，并优先覆盖当前模型漏报的攻击类型。

## 输入与输出

- 候选源：`mydata/task_107/binary_deduplicated_lora_result.xlsx`
- 测试集：`mydata/task_107/binary_chatglm3_lora_result.xlsx`
- 漏报分析：`outputs/lora-ckpt1200_aggregated_reports_20260730_150710/task_107_suite/sp_0729_qwen-3-6-27b-lora-ckpt1200/task_107_label_review.xlsx`
- 现有训练集：`mydata/task_107/train/task_107_lora_train.jsonl`
- 输出训练集：仍写入现有训练集路径，同时更新 `build_report.json`、`dataset_info.json` 和训练 YAML。

## 数据安全约束

1. 对候选源、测试集、漏报分析和现有训练集使用同一个 Payload 规范化函数。
2. 删除空 Payload、非法标签、重复 Payload 和标签冲突 Payload。
3. 候选 Payload 只要与完整测试集或漏报分析中的任一规范化 Payload 完全相同，就禁止进入训练集。
4. 最终训练集内部 Payload 必须唯一。
5. 不生成、改写或复制测试 Payload；“同类型覆盖”只能从候选源中选择不同的真实样本。

## 选择策略

### 保留现有样本

先保留现有 8,000 条训练数据。若现有样本违反空值、标签、重复、冲突或测试泄漏约束，则删除违规样本后从对应标签候选池补足。

### Yes 样本

最终需要 20,000 条。除保留的现有 Yes 样本外，按以下互斥优先级从未使用候选中选择：

1. 登录接口携带非空明文密码；
2. User-Agent 明确包含安全扫描器；
3. CONNECT 代理隧道；
4. 管理控制台、Actuator、Druid、Nacos、Swagger、CGI 或 API 路径；
5. PHP、JSP、ASP、CGI 等动态脚本路径；
6. 现有强攻击规则命中的 SQL 注入、命令执行、路径遍历、XSS、JNDI/反序列化等；
7. 其他 Yes 候选，优先选择 `chatglm3-6b_res` 与 Gold 不一致的困难样本，再用固定随机种子补齐。

稀缺类型不设虚构配额：候选中存在多少就纳入多少。当前无泄漏 Yes 候选按上述互斥优先级统计为：明文登录 12、扫描器 58、CONNECT 23、管理/API 2,040、动态脚本 4,395、其他强攻击规则 4,083、其他 Yes 12,124。

### No 样本

最终需要 20,000 条。保留合法的现有 No 样本，再从未使用 No 候选中优先选择其他模型判错的困难样本，并用固定随机种子补足。No 样本不使用攻击规则反向改标，原标签保持不变。

## 可复现性

- 固定随机种子为 `107`。
- 同一输入文件重复执行应生成字节一致的 JSONL 和一致的报告统计。
- 系统提示词和 ShareGPT 消息结构保持不变。

## 报告与验收

`build_report.json` 至少记录：

- 训练集总数及 Yes/No 数量；
- 保留旧样本数和新增样本数；
- 训练集唯一 Payload 数；
- 与完整测试集、漏报分析的精确重合数；
- Yes 各覆盖类型的最终数量和新增数量；
- 其他模型判错样本数量；
- 与漏报样本的粗粒度方法＋路径族重合数量，仅用于说明同类型覆盖，不代表数据泄漏。

验收条件：

1. 总数 40,000，Yes/No 各 20,000；
2. 唯一 Payload 40,000；
3. 与完整测试集精确重合 0；
4. 与漏报分析精确重合 0；
5. 原有合法训练样本全部保留；
6. 所有可用的稀缺漏报同类 Yes 候选均被纳入；
7. YAML 的 `max_samples` 更新为 40,000；
8. 构建器测试和最终数据审计全部通过。
