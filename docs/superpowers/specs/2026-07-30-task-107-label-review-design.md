# Task 107 标注复核筛选器设计

## 目标

为 `task_107_errors.xlsx` 中的 491 条错误样本提供基于正则规则的安全标注复核辅助。工具只筛选和排序疑似错标样本，不修改原始标签，也不把“未命中规则”等同于“请求安全”。

成功标准：

- 保留输入文件中的全部样本和原始字段。
- 对每条样本给出可追溯的规则命中、风险分、建议标签、复核等级和判断说明。
- 单独列出高置信疑似错标样本，供人工优先检查。
- 汇总各规则及各复核等级的数量。
- 可通过命令行指定输入、输出文件，并能重复执行。

## 输入与输出

### 输入

默认输入：

`outputs/lora-ckpt1200_aggregated_reports_20260730_150710/task_107_suite/sp_0729_qwen-3-6-27b-lora-ckpt1200/task_107_errors.xlsx`

要求存在以下列：

- `payload`
- `标记`
- `模型输出`

`提示词` 列可以存在，但不参与攻击规则判断。规则只分析 `payload`，避免系统提示词中的安全术语造成误命中。

### 输出

默认在输入文件同目录生成：

`task_107_label_review.xlsx`

包含三个工作表：

1. `全部错误_规则分析`
   - 保留输入的全部列及全部 491 条样本。
   - 新增：`规范化模型输出`、`建议标签`、`复核等级`、`风险分`、`规则类别`、`命中证据`、`判断说明`。
2. `高置信疑似错标`
   - 只包含满足高置信错标条件的样本。
3. `规则汇总`
   - 汇总每个规则类别的命中样本数。
   - 汇总每个复核等级和建议标签的样本数。

## 文本预处理

每条 payload 生成多个仅用于匹配的视图：

- 原始文本的小写形式。
- HTML 实体解码形式。
- URL 解码一层形式。
- URL 解码两层形式，用于识别双重编码攻击。

原始 payload 不做改写并原样写回 Excel。命中证据记录规则名和有限长度的匹配片段，不输出整段重复 payload。

## 规则体系

规则按证据强度分为强规则和中等规则。

### 强攻击规则

强规则命中时，通常能直接表明请求中包含明确的攻击语义：

- SQL 注入：`UNION SELECT`、布尔盲注、时间盲注、堆叠查询等。
- 命令注入/远程代码执行：shell 分隔符结合命令、反引号、`$()`、`wget/curl/chmod` 下载执行链等。
- 路径遍历和本地文件包含：编码或未编码的 `../` 指向敏感文件、`php://`、`/etc/passwd` 等。
- XSS：`<script>`、事件处理器、`javascript:` 等可执行上下文。
- WebShell/代码执行：PHP/JSP/ASP 执行函数、上传执行链等。
- JNDI/Log4Shell、XXE、反序列化等具有明确利用载荷的模式。

### 中等风险规则

单独出现时不足以证明攻击，但可参与排序：

- 可疑管理、执行或漏洞探测路径。
- 敏感扩展名和异常脚本路径。
- 扫描器、自动化攻击工具或异常 User-Agent。
- CONNECT 代理隧道、异常目标端口。
- 超长路径、随机化路径、异常编码密度。
- 单独出现的 SQL、shell 或文件系统关键词，缺乏完整攻击上下文。

每个规则包含：

- 唯一规则名。
- 规则类别。
- 正则表达式。
- 分值。
- 证据强度。
- 简短说明。

## 评分与复核决策

规则采用累积分值，但高置信决策必须包含至少一个强规则，不能仅靠多个弱关键词堆叠。

### 标记为 No 的样本

- 命中强攻击规则：`高置信疑似错标`，建议标签 `Yes`。
- 仅命中中等规则且累计分达到阈值：`中置信待复核`，建议标签留空。
- 无规则或分值较低：`低置信/暂未发现错标证据`，建议标签留空。

### 标记为 Yes 的样本

- 命中强攻击规则：`标签有攻击证据`，建议维持 `Yes`。
- 仅命中中等规则：`中置信待复核`，不自动建议 `No`。
- 未命中任何规则：`低置信待复核`，不自动建议 `No`。

未命中正则只能说明当前规则库没有找到证据，不能证明样本是正常请求。因此工具不会仅凭“零命中”将 Yes 改为 No。

## 脚本接口

脚本路径：

`scripts/review_task_107_labels.py`

命令行：

```bash
python scripts/review_task_107_labels.py \
  --input <task_107_errors.xlsx> \
  --output <task_107_label_review.xlsx>
```

省略参数时使用本设计中的默认路径。

执行完成后打印：

- 输入样本数。
- 高/中/低复核等级数量。
- 高置信疑似错标数量。
- 输出文件路径。

输入文件不存在、缺少必需列、标签不是 Yes/No 时，脚本以明确错误信息退出，不生成不完整结果。

## 测试

测试文件：

`tests/test_review_task_107_labels.py`

测试覆盖：

- 明确 SQL 注入命中强规则并建议 Yes。
- 命令注入和下载执行链命中强规则。
- 单层及双层 URL 编码路径遍历可被识别。
- 普通请求不会被强规则误判。
- `标记=No` 且命中强规则时进入高置信结果。
- `标记=Yes` 且无规则命中时只进入低置信待复核，不建议 No。
- 提示词中的 “web attack” 等词不会参与 payload 规则匹配。
- 模型输出可规范化为 Yes、No 或 Other。
- 输入缺列时拒绝处理。
- 生成的三个工作表存在，样本数和汇总数量一致。

## 安全边界

- 工具是数据审计辅助，不是标签真值生成器。
- 所有建议标签必须由人工复核后才能回写原始训练或测试数据。
- 规则会存在漏报；扫描、滥用代理、未授权访问和业务逻辑攻击通常需要上下文，正则不能独立判定。
- 输出必须保留规则证据和说明，避免不可解释的自动判定。
