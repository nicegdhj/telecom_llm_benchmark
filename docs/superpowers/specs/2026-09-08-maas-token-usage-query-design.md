# MaaS Token 用量查询页面设计

## 1. 目标

在现有 Score 平台中增加“Token 用量查询”功能。用户输入时间范围和一组 MaaS 接口标识（`names`），选择按小时或按天拆分查询。平台通过后端代理访问私域 MaaS 统计接口，展示每个时间段的原始统计结果和完整时间范围的原生汇总结果。

平台不对返回指标自行求和、求平均或二次计算。

## 2. 现有 MaaS 接口

- 地址：`http://188.108.11.94:31567/model/stat/query`
- 方法：`POST`
- 请求头：`Content-Type: application/json`
- 本功能使用的请求字段：
  - `names`: 前端当前所有非空 Name 值组成的数组。
  - `startTime`: `yyyy-MM-dd HH:mm:ss`。
  - `endTime`: `yyyy-MM-dd HH:mm:ss`。
- 成功响应：`code=200`，统计指标位于 `data`。
- 多个 `names` 的合并统计由 MaaS 接口完成，Score 平台仅展示返回值。

MaaS 地址由后端环境变量 `EVAL_BACKEND_MAAS_STAT_URL` 配置，默认为上述已验证地址。

## 3. 前端页面

### 3.1 导航和路由

- 左侧导航新增“Token 用量查询”。
- 页面路由为 `/token-usage`。
- 沿用现有登录保护，所有已登录角色可访问。

### 3.2 查询条件

页面顶部提供：

1. 开始时间，精度到小时。
2. 结束时间，精度到小时。
3. 统计维度：“天”或“小时”，默认为“天”。
4. Names 配置列表，每行包含：
   - 友好名称（K）：仅用于前端识别，不发送给 MaaS。
   - 接口标识（V）：发送给 MaaS 的 `names` 值。
5. Names 列表支持增加、删除和修改。默认预填：
   - `接口 1` → `d29a854f-5b1f-4da9-9a1e-caecacfd1156`
   - `接口 2` → `76816616-c232-404c-bbb8-c950549231ee`

提交前校验：

- 开始和结束时间必填。
- 结束时间必须晚于开始时间。
- 至少保留一个非空 Name 值。
- 空行不进入 `names` 数组。

### 3.3 结果展示

- 结果表每行对应一个分段查询的 MaaS 原始返回。
- 表格首列为统计区间，其余列展示 MaaS `data` 中的全部指标：
  - `keyNum`、`serviceNum`、`apiNum`、`callCount`、`exceptionCount`
  - `successRate`、`tokenUsage`、`avgTokenUsage`、`avgRequestTokenUsage`
  - `avgDelay`、`avgTimeToFirstToken`、`avgTokenSpeed`、`avgTokenThroughput`
  - `httpClientErrorAlerts`、`httpServerErrorAlerts`
  - `avgEndToEndTps`、`avgModelOutputTokenTps`、`timeToPerToken`、`dataTypeList`
- 宽表格使用横向滚动，统计区间列保持可见。
- 数值保留 MaaS 返回的精度；成功率增加 `%` 显示，耗时指标增加 `ms` 显示。
- 表格最后显示“汇总”行。该行来自完整原始时间范围的独立 MaaS 查询，不由分段行计算。
- 页面在表格上方展示本次查询使用的 K-V 列表，便于识别统计范围。

## 4. 时间拆分规则

所有区间按左闭右开理解，但发送给 MaaS 时仍使用选定的起止时间字符串。时间选择器只产生整小时值，分秒固定为 `00:00`。

### 4.1 按小时

从开始时间起每小时切分一段，最后一段截止到实际结束时间。

示例：`2026-09-01 10:00 → 2026-09-01 13:00` 拆为：

- `10:00 → 11:00`
- `11:00 → 12:00`
- `12:00 → 13:00`

### 4.2 按天

以每日 `00:00` 为边界切分。首尾不足一天时保留用户选择的实际边界，不补齐至范围外。

示例：`2026-08-31 10:00 → 2026-09-02 14:00` 拆为：

- `2026-08-31 10:00 → 2026-09-01 00:00`
- `2026-09-01 00:00 → 2026-09-02 00:00`
- `2026-09-02 00:00 → 2026-09-02 14:00`

## 5. 后端设计

### 5.1 Score 平台接口

新增：

```text
POST /api/v1/token-usage/query
```

请求体：

```json
{
  "names": [
    {"label": "后端 API", "value": "d29a854f-5b1f-4da9-9a1e-caecacfd1156"},
    {"label": "开放订阅 API", "value": "76816616-c232-404c-bbb8-c950549231ee"}
  ],
  "startTime": "2026-08-31 00:00:00",
  "endTime": "2026-09-03 14:00:00",
  "granularity": "day"
}
```

响应体包含：

- `names`: 清理后的 K-V 列表。
- `rows`: 各分段的起止时间、返回指标或错误信息。
- `summary`: 完整时间范围的 MaaS 原始统计结果或错误信息。

### 5.2 调用流程

1. 校验时间、统计维度和 Names。
2. 从 K-V 列表提取所有非空 V，组成 MaaS `names` 数组。
3. 按规则生成分段区间。
4. 后端最多并发 4 个请求调用 MaaS，避免小时级长时间范围造成过多同时请求。
5. 用完整原始时间范围再查询一次，作为 `summary`。
6. 返回分段结果和汇总结果，不修改 MaaS 指标值。

调用 MaaS 时设置连接和总超时，并校验 HTTP 状态码、JSON 格式与业务 `code`。

## 6. 错误处理

- Score 请求参数不合法：返回 `422`，前端在查询条件附近显示错误。
- MaaS 连接超时、HTTP 错误、非 JSON 响应或 `code != 200`：
  - 分段请求失败时，该分段保留在表格中并显示失败原因，不丢弃其他成功分段。
  - 汇总请求失败时，汇总行显示失败原因，不用分段结果代替。
- 查询过程中按钮进入加载状态，防止重复提交。

## 7. 测试与验收

### 7.1 后端自动测试

- 按小时拆分整小时区间。
- 按天拆分跨天区间，并保留首尾实际边界。
- 两个 Name 值在每个分段和汇总请求中都完整传入。
- 每个分段返回值原样保留。
- 完整时间范围的返回用作汇总，不计算分段和或平均。
- MaaS 单个分段失败时，其他分段仍能返回。
- 未登录请求被拒绝。

### 7.2 前端验收

- 左侧导航可进入“Token 用量查询”页面。
- 页面默认显示两个可编辑 K-V Name。
- 时间可选到小时，默认按天查询。
- 按小时和按天查询均能显示对应分段。
- 表格展示所有 MaaS 指标，并可横向滚动。
- 最后一行是 MaaS 完整区间返回的汇总值。
- 页面不对 MaaS 数值执行求和、平均或推导计算。

## 8. 范围边界

本次不包含：

- 查询条件持久化和历史查询记录。
- Token 费用换算。
- 图表趋势分析或导出。
- 按 `names` 分开统计。MaaS 对多个 `names` 的合并结果是本页面的唯一数据口径。
