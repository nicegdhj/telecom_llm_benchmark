# 垂类大模型评测平台 · 用户使用手册

> 面向**使用者**（不需要懂代码、不需要改平台）。读完即可独立完成：配置模型 → 发起测评 → 看执行 → 看结果 → 做对比导出。

---

## 1. 这个平台是做什么的

给「被测大模型」在一批「评测任务（数据集）」上跑题，并由「打分模型/规则」自动评分，最终得到**每个模型 × 每个任务**的准确率、质量与逐条明细，支持多模型横向对比与结果导出。

一次完整评测分两步，平台会自动调度：

1. **推理**：被测模型对数据集逐条作答，产出"模型输出"。
2. **评测（评分）**：用规则或打分模型，把"模型输出"和"标准答案"比对，算出准确率。

## 2. 登录与角色

浏览器打开平台地址，用账号密码登录。左侧是导航栏，底部显示当前用户与角色。

| 角色 | 能做什么 |
|------|----------|
| **访客 (viewer)** | 只读：浏览所有页面、看结果与日志，不能新建/修改 |
| **操作员 (operator)** | 在访客基础上，可新增模型、发起测评、重跑、上传数据集 |
| **管理员 (admin)** | 全部权限，外加「用户管理」 |

> 看到按钮置灰且提示"需要操作员或管理员权限"，说明当前角色无权操作，请联系管理员。

## 4. 标准使用流程（先记住这张图）

```
①配置评测模型 ─┐
②配置打分模型 ─┼─→ ③测评管理·创建任务 ─→ ④执行记录看进度/日志 ─→ ⑤测评管理·详情看结果 ─→ ⑥测评分析·对比/导出
```

下面按顺序逐步说明。

## 5. 准备工作

### 5.1 配置「评测模型」（被测模型）

进入 **评测模型 → 新增模型**。先选 **Config_Key**（决定要填哪些字段）：

| Config_Key | 适用场景 | 主要字段 |
|------------|----------|----------|
| `local_qwen` | 本地 vLLM 部署的垂类模型 | 模型名、Host IP、端口、并发数 |
| `maas_gateway` | 带网关鉴权的 MaaS 服务 | 模型名、API Key、鉴权头名、Host、端口、完整 URL、并发数 |
| `common_gateway` | 通用大模型 API（如百炼/兼容 OpenAI） | 模型名、API Key、API URL、并发数 |

- **配置名称**：给这个模型起个好认的名字（如 `common_deepseek`），列表和报表里都用它。
- **模型名**：服务端真正的模型标识（如 `qwen-plus`、`deepseekv3.1-w8a8`）。
- **并发数**：同时发多少请求，按服务端承受能力填（默认 20）。

填好后，建议点该模型卡片上的 **连通性测试**：成功显示 `ok`，失败会**原样显示报错**（据此排查地址/密钥/网络）。

### 5.2 配置「打分模型」（裁判，按需）

进入 **打分模型 → 新增**。用于需要"模型来判分"的任务（如开放问答）。规则类任务（精确匹配/JSON 字段比对）**不需要**打分模型。同样支持 **连通性测试**。

> 创建测评时，「打分模型」可选"不使用"。但如果任务的评估器需要打分模型却没配，评测会失败并提示（如 `未配置打分模型：请设置 SCORE_MODEL_NAME …`）。

### 5.3 任务与数据（按需上传数据集）

进入 **任务与数据**。每个评测任务都有**固定的数据路径和评估器**，平台已内置初始版本，开箱即用。

如需用自己的数据：点任务卡片 **详情/管理 → 上传数据集**，填**版本标签 (Tag)**、选 **JSONL 文件**、可勾"设为默认"。上传后该任务就多了一个可选版本，创建测评时可指定用哪个版本。

---

## 6. 发起测评（测评管理 · 创建任务）⭐

进入 **测评管理 → 创建任务**，填写：

| 字段 | 说明 |
|------|------|
| **任务名称** | 必填，本次评测的名字（如"0623 三模型对比"） |
| **模式** | `推理+评测`（默认，端到端）/ `仅推理` / `仅评测` |
| **选择评测模型** | 勾选一个或多个被测模型（多选即多模型对比） |
| **选择评测任务** | 勾选一个或多个任务；勾选后可为每个任务选**数据集版本**（默认用初始/默认版本） |
| **评测版本** | 评分产物的版本标签，默认 `eval_init`，一般不用改 |
| **打分模型** | 需要裁判的任务在此选；不需要选"不使用" |
| **备注** | 选填 |

点 **创建**。任务会被拆成「模型 × 任务」的最小**单元**并**自动排队执行**。创建后可直接去 **执行记录** 看实时状态。

> 列表里每行任务可「查看」测评配置 JSON；点 **重试** 可用相同配置重新发起一次。

---

## 7. 查看执行与日志（执行记录）

进入 **执行记录**，每一行是一个执行中的"测评任务"（某模型某任务的一次推理或评分）。可按状态筛选、按任务 ID 搜索。

**状态含义：**

| 状态 | 含义 |
|------|------|
| 待执行 | 已排队，等待调度 |
| 运行中 | 正在跑 |
| 成功 | 正常完成 |
| 失败 | 出错（鼠标看 `err` 提示，或看日志） |
| 已取消 | 被手动取消 |

**点「查看」看日志**，弹窗内有两个标签页：

- **执行日志**：平台包裹容器运行的标准输出（看调度、命令、整体流程）。
- **框架日志**：评测框架内部更细的日志（看每条样本、报错堆栈）。**运行中也会自动刷新（每 5 秒）**，便于实时盯进度；也可手动「立即刷新」或下载 `.txt`。

> 即使容器"正常退出"，只要框架日志里出现报错（如 Python 堆栈、任务 error），平台也会把该任务判为**失败**，不会假成功。失败原因会显示在执行记录与单元历史里。

运行中的任务可点 **取消**。

---

## 8. 查看结果（测评管理 · 详情）⭐

在 **测评管理** 点任意一行（或 → 箭头）进入**详情**页。

### 8.1 结果矩阵

顶部是「模型 × 任务」矩阵，每个格子（**单元**）显示该模型在该任务上的准确率与样本数。点格子，下方展开该单元的详情。

### 8.2 单元详情

- **三要素卡片**：准确率、耗时（推理/评分）、样本数。
- **历史时间线**：该单元每次推理/评分的记录（版本号、状态、准确率、耗时、时间）。
  - **切到此版本**：同一单元可能有多个版本，点此把"当前展示版本"切过去。
  - **日志**：打开该次执行的日志（同第 7 节）。
  - **结果展示**（评分成功的行才有）：点开在下方内联展示——
    - **执行质量**：本次评分中"好"的占比 + 三色条（好 / 空输出 / 解析失败）。
      - **好** = 模型有输出且评估器成功解析（无论答案对错）；
      - **空输出** = 模型没产出内容；**解析失败** = 有输出但评估器没解析出来。
      - 它和"准确率"是两回事：准确率看答得对不对，执行质量看这次跑得"干不干净"。
    - **抽样明细**：前 10 条样本的「输入 / 模型输出 / 参考答案 / 评分」，用于快速核对效果。

### 8.3 重跑此单元

点右上 **重跑此单元**，可选：

- **推理 + 评分** / **仅推理** / **仅评分**。
- 选 **仅评分** 时，需选一个已成功的推理版本作为基础；并可**重新选择评分模型**（不选则沿用批次默认）——适合换裁判重新打分。

## 9. 多结果对比与导出（测评分析）

进入 **测评分析**：

1. 填**分析任务名**（必填）。
2. 用顶部**筛选**面板按 模型 / 任务 / 批次 圈定范围（默认"全部"，三列同屏勾选，点一次 **确认** 生效）。
3. 在候选列表里**勾选**要对比的评测结果（同一单元多版本可在行内切换版本）。
4. 点 **开始对比** 进入对比视图（柱状/雷达等图表横向比较各模型表现）。
5. 需要存档：结果会保存为左侧的**分析任务**，下次可直接点开复用；**分析复用**可基于当前配置另存一份。
6. 点 **导出 zip**：打包对比汇总 + 每个评测的逐条明细（含 `eval_res / 模型输出 / 参考答案 / token` 等）。

## 10. 常见问题（FAQ）

**Q1. 创建了任务但一直"待执行"？**
平台按模型并发与全局并发排队，前面任务跑完会自动轮到；耐心等或去执行记录看运行中数量。

**Q2. 任务"成功"但准确率 0%？**
先看单元「结果展示」的执行质量：若大量"空输出"，多半是被测模型接口异常（限流/超时/鉴权），去"评测模型"做连通性测试；若"解析失败"多，说明模型输出格式不符合该任务要求。

**Q3. 评分任务失败，提示未配置打分模型？**
该任务的评估器需要裁判模型。重跑选"仅评分"并指定一个打分模型，或在创建测评时配好"打分模型"。

**Q4. 运行中看不到框架日志？**
日志弹窗切到「框架日志」标签，运行中每 5 秒自动刷新；若仍为空，说明框架刚启动还没产出，稍等即可。

**Q5. 想用相同配置再跑一次？**
测评管理列表里点该任务的 **重试**；或对单个格子用 **重跑此单元**。

## 11. 名词速查

| 名词 | 含义 |
|------|------|
| 评测模型 | 被测的大模型 |
| 打分模型 / 裁判 | 给主观题打分的模型 |
| 任务 / 数据集 | 一套带标准答案的题目 |
| 批次 / 测评任务 | 一次"模型×任务"的评测作业 |
| 单元 (cell) | 矩阵里"某模型×某任务"的最小格子 |
| 推理 | 模型作答阶段 |
| 评测 / 评分 | 比对答案算分阶段 |
| 准确率 | 答对比例 |
| 执行质量 | 本次评分中"好"（有输出且可解析）的比例 |
| 版本 | 同一单元多次执行的产物（v1_infer / v1_score …） |
